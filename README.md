# GPS-spoofing-detection-and-Secure-Time-Synchronisation
Honours (Networks and Security) Final year project 
A simulation-based system that detects GPS/GNSS spoofing attacks against network time synchronization and automatically fails over to a trusted backup time source. Built around the idea that GPS is not just navigation , it's a **Stratum-0 timing source** that critical infrastructure (5G, banking, power grids, data centers) depends on, and that dependency is rarely defended.

---

## ⚠️ Scope & Disclaimer

This project is **entirely simulation-based**. No RF signals are transmitted, no real GNSS receivers are interfered with, and no live spoofing of an operational system is performed. All "spoofing" is done by generating and modifying **NMEA log files** (recorded or synthetic GPS data) that are then fed into the detection pipeline. This project studies detection algorithms, not RF attack techniques.

---

## Why This Matters

GPS satellites broadcast highly precise timing data generated by onboard atomic clocks. Networks distribute this time via NTP/PTP to synchronize routers, servers, financial systems, telecom base stations, and power grid equipment. If a GPS receiver is fed spoofed signals, it can silently report a false time and every downstream device that trusts it inherits the error. Unlike jamming (which is immediately obvious), spoofing is designed to be invisible.

This project inserts a **trust evaluation layer** between the GPS receiver and the time server, so bad timing data is caught and rejected before it propagates.

```
GPS Satellites → GPS Receiver → [ Spoof Detection Layer → Trust Engine ] → Secure Time Server → Clients
```

## Detection Mechanisms

| Mechanism | What it checks |
|---|---|
| **Position/Velocity Validation** | Flags physically impossible implied speed between consecutive GPS fixes |
| **Time Offset Validation** | Compares GPS-derived time against a reference (Internet NTP) time source |
| **Satellite Health Monitoring** | Watches satellite count, HDOP, and SNR for abnormal shifts |
| **Trajectory Analysis** | Detects implausible acceleration/turning patterns across a position history |
| **Trust Scoring Engine** | Combines all indicators into a single 0–100 trust score, both via a fixed-weight baseline and a data-derived (ML) model |
| **Secure Failover / Holdover** | Switches to a backup time source (Internet NTP or local oscillator model) when GPS is rejected, and tracks clock drift during holdover |

## Evaluation

The system is benchmarked against:
1. A **naive single-threshold baseline** (e.g., flag if speed exceeds a fixed limit)
2. A **fixed-weight trust score** (rule-based, manually assigned weights)
3. A **data-derived / learned trust score** (weights fit via logistic regression on labeled clean/spoofed data)

Metrics reported: Precision, Recall, F1-score, False Positive Rate, and Detection Latency, alongside an ablation study measuring each detector's individual contribution to overall performance.



---



## Limitations

- No RF-layer testing — detection is validated against NMEA-level data (recorded and/or synthetic), not raw signal captures
- Effectiveness against very slow, low-magnitude drift attacks depends on threshold/window tuning and is discussed in the evaluation section
- Dataset availability at the NMEA level is limited; where public datasets weren't accessible, synthetic attack scenarios were used and documented
